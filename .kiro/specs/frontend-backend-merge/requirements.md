# 需求文档

## 简介

将干细胞治疗档案管理系统的前端和后端合并为统一端口服务，使用 Express.js 同时提供 API 接口和静态文件服务，简化部署和运维流程。

## 术语表

- **后端服务器 (Backend_Server)**: Express.js 后端服务器，提供 API 接口
- **前端资源 (Frontend_Assets)**: 前端静态资源文件（HTML、CSS、JavaScript、字体、图片等）
- **统一服务器 (Unified_Server)**: 合并后的统一服务器，同时提供 API 和静态文件服务
- **静态中间件 (Static_Middleware)**: Express.js 静态文件中间件，用于托管前端资源

## 需求

### 需求 1：静态文件服务

**用户故事：** 作为运维人员，我希望后端服务器能够托管前端静态文件，以便通过单一端口访问整个应用。

#### 验收标准

1. 当用户访问根路径 `/` 时，统一服务器应返回 `login.html` 页面
2. 当用户访问 `/*.html` 路径时，统一服务器应返回对应的 HTML 文件
3. 当用户访问 `/css/*` 路径时，统一服务器应返回对应的 CSS 文件
4. 当用户访问 `/js/*` 路径时，统一服务器应返回对应的 JavaScript 文件
5. 当用户访问 `/webfonts/*` 路径时，统一服务器应返回对应的字体文件
6. 当用户访问 `/assets/*` 路径时，统一服务器应返回对应的资源文件
7. 当用户访问不存在的静态文件时，统一服务器应返回 404 错误页面

### 需求 2：API 路由优先级

**用户故事：** 作为开发人员，我希望 API 路由优先于静态文件路由处理，以确保 API 接口正常工作。

#### 验收标准

1. 当请求路径以 `/api/` 开头时，统一服务器应优先匹配 API 路由处理器
2. 当 API 路由未匹配时，统一服务器应继续尝试匹配静态文件
3. 统一服务器应保持所有现有 API 端点的功能不变

### 需求 3：前端配置更新

**用户故事：** 作为开发人员，我希望前端配置能够自动适应合并后的部署方式，无需手动修改 API 地址。

#### 验收标准

1. 当前端运行在合并服务器上时，前端配置应使用相对路径 `/api` 作为 API 基础地址
2. 当前端检测到开发环境（端口 8080）时，前端配置应继续使用独立的后端地址
3. 前端配置应支持同时在开发模式和生产模式下正常工作

### 需求 4：跨域配置调整

**用户故事：** 作为安全工程师，我希望合并后的服务器能够正确处理跨域请求，同时保持开发环境的灵活性。

#### 验收标准

1. 当请求来自同源时，统一服务器应正常处理请求
2. 当处于开发环境时，统一服务器应允许来自 localhost:8080 的跨域请求
3. 当处于生产环境时，统一服务器应限制跨域请求来源

### 需求 5：目录结构调整

**用户故事：** 作为开发人员，我希望项目目录结构清晰，便于维护和部署。

#### 验收标准

1. 统一服务器应从 `public/` 目录提供静态文件服务
2. 部署时，前端文件应被复制到 `backend/public/` 目录
3. 项目应提供脚本自动完成前端文件的复制操作

### 需求 6：健康检查端点

**用户故事：** 作为运维人员，我希望能够检查合并后服务器的运行状态。

#### 验收标准

1. 当访问 `/health` 端点时，统一服务器应返回服务器状态信息
2. 健康检查响应应包含服务器版本、运行时间和数据库连接状态

### 需求 7：错误处理

**用户故事：** 作为用户，我希望在访问不存在的页面时能够看到友好的错误提示。

#### 验收标准

1. 当用户访问不存在的 API 端点时，统一服务器应返回 JSON 格式的 404 错误
2. 当用户访问不存在的页面时，统一服务器应返回 HTML 格式的 404 错误页面
3. 如果服务器发生内部错误，统一服务器应记录错误日志并返回友好的错误信息
